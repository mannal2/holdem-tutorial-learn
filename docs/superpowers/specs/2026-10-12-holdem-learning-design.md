# 한 판씩 — 25개 레슨 학습·디자인 명세

작성: 2026-10-12. 대상: 다음 구현 담당 Sol. 상태: 사용자 검토용 명세. 이번 산출물은 계획이며 앱 구현 완료를 의미하지 않는다.

## 1. 목적과 확정된 방향

사용자는 글로 읽은 규칙을 실제 테이블에서 떠올리기 어렵다. 특히 배분 순서, 행동 순서, 가능한 행동, 족보를 시각적 사건과 연결해야 한다. 한 화면에서 짧게 보고 직접 판단한 뒤 테이블의 변화를 확인하게 만든다.

- 사용자가 제시한 25개 레슨의 순서와 범위를 따른다. 최근 요청의 18·19번 족보 레슨도 포함한다.
- 기존 React 프로토타입의 디자인, 테이블 배치, 촉감 있는 카드·칩 애니메이션을 유지한다.
- 사용자 확정: 3~17번은 한 판 중심이며 다른 예시가 필요한 곳만 별도 연습으로 분리한다.
- 사용자 확정: 25번은 고정 카드·상대 행동으로 구성된 문제 풀이이다. 자유 플레이나 상대 AI를 만들지 않는다.
- 계획 작성과 실제 구현을 분리한다. Sol은 공통 기반부터 만든 뒤 사용자가 지정한 레슨만 하나씩 구현한다.
- 사용자 확정: 레슨 자유 선택과 현재 브라우저의 진도 저장. 기존 상단 목차를 복원하지 않고 설명 패널의 작은 버튼으로 목록을 연다.

## 2. 교육 전제

6인 노리밋 텍사스 홀덤, SB 5 / BB 10, 앤티 없음, 레이크 없음, 정수 칩을 기본으로 한다. 24번만 처음부터 2인 테이블로 시작한다. 20번은 재진입 없는 토너먼트 예시이며 실제 대회 전체를 시뮬레이션하지 않는다.

수익 전략, 프리플랍 레인지, 확률 계산, 배팅 추천은 가르치지 않는다. 합법 행동이 여러 개인데 하나를 포커 정답이라고 처리하지 않는다. 학습상 특정 행동을 요청할 때는 “이번에는 콜을 연습해요”라고 명시한다.

1·17번은 족보 이름과 가장 좋은 다섯 장 선택을 안내하는 레슨이다. 체계적인 족보 암기와 동률 비교는 18·19번에서 진행한다. 18번 이전 문제에 미학습 족보 서열을 정답 조건으로 몰래 넣지 않는다.

모든 연습은 다시 시도할 수 있다. 시간 제한, 생명, 순위표, 현금 표시, 베팅을 부추기는 연출은 필요 없다.

### 3.1. 패널 높이와 스크롤 — 사용자 확정 규칙

- 데스크톱(800px 초과)은 왼쪽 테이블과 오른쪽 설명 패널의 윗선을 맞춘다. 두 패널의 아랫선은 달라도 된다.
- 테이블 패널과 내부 table-stage 높이는 같은 화면 크기에서 항상 일정하게 유지한다. 설명·질문·정답·오답·힌트 길이가 달라져도 테이블, 펠트, 카드, 플레이어 위치가 세로로 늘어나거나 움직이지 않아야 한다.
- 테이블 높이는 화면 폭별 반응형 기준으로 정할 수 있다. 고정이란 모든 기기에서 같은 픽셀 수라는 뜻이 아니라, 같은 화면 크기에서 레슨 내용에 영향을 받지 않는다는 뜻이다.
- 오른쪽 설명 패널만 기본 최소 높이를 두고 내용에 따라 아래로 늘어난다. 테이블과 설명 패널의 높이를 강제로 같게 맞추지 않는다.
- 구현 시 grid의 stretch 정렬과 table-stage의 flex 성장으로 테이블이 설명 패널을 따라 늘어나는 구조를 해제한다. 높이 고정은 데스크톱에만 적용하고 모바일 규칙을 덮어쓰지 않는다.
- 일반적인 데스크톱 창과 기본 글자 크기에서는 테이블·설명·핵심 조작이 화면 안에 들어오는 것을 기본 목표로 한다. 설명이 길어지면 먼저 학습 단계를 나누며, 설명 패널에 별도 내부 스크롤을 기본으로 넣지 않는다.
- 모바일(800px 이하)은 테이블 위·설명 아래 배치를 유지한다. 설명이 길어지면 페이지의 자연스러운 세로 스크롤을 허용한다.
- 데스크톱에서도 창 높이가 매우 작거나 글자를 확대했다면 필요한 페이지 스크롤을 허용한다. 화면에 억지로 넣기 위해 내용을 자르거나 글자를 줄이지 않는다.
- 테이블의 sticky 고정은 기본 기능으로 추가하지 않는다.

이 규칙은 향후 구현에 적용할 공통 요구사항이다. 이번 문서 갱신은 현재 앱의 CSS를 수정한 것이 아니다. 기존 캡처는 테마·구성 참고로 보존하되, 패널 높이 동작은 이 확정 규칙을 우선한다.


### 애니메이션 학습 속도 — 사용자 확정(2026-10-13)

- 모든 레슨은 src/animation.mjs의 animationTiming과 공통 재생 함수를 사용한다. 레슨 데이터나 개별 컴포넌트에 별도 속도를 하드코딩하지 않는다. 새로운 효과가 필요한 경우에도 공통 기준에 맞춰 정의하고 기존 효과의 속도를 우회하지 않는다.
- 일반 모션 기준: 카드 배분360ms, 칩 이동450ms, 폴드520ms, 체크 두 번 노크760ms. 베팅·콜·레이즈·칩 반환·팟 지급은 같은450ms 칩 이동을 사용한다.
- 실제 행동 없는 순서 미리보기는 자리 강조220ms → 관찰 유지450ms → 결과 멈춤330ms로 약1초씩 진행한다. 카드·칩을 움직이지 않고 베팅/체크 또는 행동 순서 소비로 기록하지 않는다.
- 행동 전 플레이어 강조220ms, 행동 후 결과 멈춤330ms, 카드 한 장 배분 후 멈춤200ms를 사용한다. 누구의 행동인지와 도착 결과를 읽을 시간을 확보하며 모든 효과에 동일한 배율을 적용하지 않는다.
- 폴드 카드는 아래로 내려가며 사라진 뒤 원래 카드 모습으로 돌아오거나 깜빡이지 않는다. 사라진 최종 프레임을 폴드 상태가 화면에 반영될 때까지 유지하고 효과를 정리한다. 폴드 후 빈 카드 슬롯의 테두리, 어두워진 좌석과 폴드 표시는 유지한다. 재생 취소 시 유지된 효과도 정리한다.
- 체크 파문은220ms로 재생하고, 노크 전체 시간의28%와66% 지점에 시작해 손의 두 접촉과 동기화한다. 체크를 늦춰도 두 번 노크 리듬과 칩 이동 없음은 유지한다.
- 모션 감소 설정에서는 시각 이동을 생략하고 각 공통 대기는60ms로 유지한다. 일반 모션을 늦췄다는 이유로 모션 감소 대기도 늘리지 않는다.
- 속도와 규칙 상태를 분리한다. 칩/카드 상태는 이동 완료 후에만 확정하며, 취소/반복 재생에서도 중복 지급이나 늦은 상태 변경이 없어야 한다.
- 신규 레슨 검증에서 공통 속도 사용, 체크 접촉/파문 동기화, 이동 완료 전 상태 유지, 취소와 모션 감소 동작을 확인한다. 순차 배분/행동의 테스트 대기는 실제 재생 완료를 기다리며, 이전 속도의 고정 시간에 의존하지 않는다.

### 공통 순서 화살표 — 사용자 확정(2026-10-13)

- 모든 레슨의 순서 안내는 DirectionArrow 공통 컴포넌트를 사용한다. 데이터에는 direction:{from:플레이어ID,to:플레이어ID,onHint?:true}만 지정하며 모바일/데스크톱별 SVG 좌표나 경로 문자열을 하드코딩하지 않는다.
- 실제 렌더링된 출발/도착 플레이어 설명 박스의 경계와 테이블 크기를 측정해 경로를 계산한다. 출발점·화살표 끝은 설명 박스에서12px 떨어뜨리고, 머리는 길이/너비10px, 선은2px로 유지한다. 박스 위에 화살표를 겹쳐 올려 가독성 문제를 해결하지 않는다.
- 경로는 이웃한 자리 사이의 테이블 가장자리를 따르며 중앙 팟·보드를 가리지 않는다. 세로로 이어진 좌석은 왼쪽/오른쪽 바깥으로 볼록한 곡선을 사용한다. 곡선 폭은 실제 바깥 여백에 맞춰 줄이고, 좌우 좌석 바깥에 최소22px 공간을 확보한다.320px에서는 덱 위치도 카드와 겹치지 않도록 조정한다. 대각선 경로는 기존 계산을 유지한다. 카드·역할 배지·라벨과도 겹치지 않도록 현재 레슨 경로를 검증한다. 레슨05의첫행동자/정답/뒤쪽순서화면도8개폭(320/390/475/800/801/902/1100/1366)에서 실제 경로를 검사한다.
- ResizeObserver로 테이블·설명 박스·좌석 영역 크기를 관찰하고, 파트가 바뀔 때도 위치를 다시 측정한다.800px 경계에서 레이아웃이 바뀌거나 설명 박스 크기가 달라져도 같은 간격과 머리 크기를 유지한다. 숨김/힌트 조건은 기존 레슨 데이터대로 유지한다.
- 새 순서 경로를 추가하면320/390/475/800/801/902/1100/1366px에서 실제 창 크기를 변경하며 머리/선의 겹침·잘림 없음,12px 간격과10px 머리 크기를 확인한다. 기존 칩/카드 이동과 레슨 진행을 변경하지 않는다.

### 공통 테이블의 문구와 카드 위 라벨 — 사용자 확정(2026-10-13)

- 공통 Table에서 펠트의 ‘한 판씩’ 워터마크와 보드 아래 상시 안내를 제거한다. ‘공용카드 N장’, ‘공용카드는 아직 없어요’, ‘모두 함께 쓰는 공용카드’ 등의 상시 시각 문구를 신규 레슨에서 복원하지 않는다. 모든 테이블 모드에 적용한다.
- 공용카드를 처음 배우는 레슨에서는 해당 파트의 설명창으로 개념을 안내한다. 화면 읽기 도구용 보드 설명(aria-label)은 유지한다.
- 행동·결과 라벨은 좌석의 고정 top 좌표 대신 해당 개인카드 영역 위에 배치한다. 카드 영역은 카드의 실제 높이에 맞게 늘어나고, 라벨 아래와 카드 위 사이에6px 간격을 확보한다. 강조 테두리까지 고려해 시각적 겹침이 없어야 한다. 카드 강조 크기는 유지하며 가독성 문제를 해결하려고 라벨 글자를 더 작게 줄이지 않는다.
- 모바일에서 위 라벨과 중앙 보드도 겹치지 않아야 한다. 새 카드 크기·강조 효과를 도입할 때 카드/라벨/보드 간격을 함께 확인한다. 테이블 높이를 설명 길이에 따라 늘리는 방식으로 해결하지 않는다.
- 새 레슨 구현 시 공통 컴포넌트를 재사용하고320/390/475/1366px에서 상시 문구 없음, 라벨과 카드·보드의 겹침 없음, 카드 배분 슬롯 착지·테이블 높이 유지 여부를 검증한다.

### 완료 버튼·애니메이션 재생·카드 여백 — 사용자 확정(2026-10-13)

- 레슨 완료 화면의 큰 주 버튼은 바로 다음 번호의 정식 레슨이 구현된 경우 ‘다음 레슨: 제목 →’으로 표시한다. 클릭하면 그 레슨의 첫 단계로 이동하고 완료 기록은 유지한다. 미구현 수업을 건너뛰거나 첫걸음 체험을 정식 순서에 끼우지 않는다.
- 다음 레슨이 있으면 ‘이 레슨 다시 연습 ↻’은 주 버튼 아래 보조 버튼으로 배치하고 터치 높이는 최소44px를 유지한다. 다음 레슨이 미구현이거나 마지막 수업이면 재연습을 큰 주 버튼으로 유지한다. 완료 화면에는 애니메이션 다시 보기 버튼을 표시하지 않는다.
- 애니메이션 다시 보기는 이미 본 애니메이션을 반복한 뒤에도 현재 결과·질문 파트에 그대로 머무르는 경우에만 표시한다. 처음 재생하고 다음 파트로 진행하는 화면, 재생 경로가 없는 정적 설명·질문, 레슨 완료 화면에서는 숨긴다. 현재 파트의 replayFrom이 같은 시나리오의 재생 구간을 가리키고, 그 구간의 끝(playTo)이 현재 checkpoint와 일치할 때만 허용한다. 현재 파트 자체에 처음 진행할 playTo가 있으면 다시 보기 버튼을 표시하지 않는다.
- 버튼은 ‘↻ 애니메이션 다시 보기’로 표시한다. 재생 중에는 ‘↻ 다시 보는 중…’으로 표시하고 비활성화하여 중복 재생을 막는다. 일반 진행은 주 버튼이 담당한다. 다시 보기에서는 stepId·제목·질문·진행률·오답/힌트·선택 상태를 유지하고, 재생 완료 시 현재 파트의 원래 확정 테이블 상태를 복구한다. 자동으로 다음 파트로 이동하거나 진도/완료 조건을 추가하지 않는다. 질문 답변과 주 버튼도 재생 중에는 비활성화한다. 이전·레슨 변경·리사이즈·새로고침에 의한 취소 시 늦은 카드/칩 변경이 없어야 한다.
- 카드 바깥 크기·착지 슬롯·뒷면 패턴은 보존한다. 숫자/무늬를 내부의 위/아래 두 행에 배치하고, 내용 영역의 상하 여백은 카드 내부 높이의8%, 좌우는 내부 너비의12%로 유지한다. 숫자는 내부 높이의40%, 무늬는34% 크기와 line-height:1을 사용한다. 무늬에 따라 실제 잉크 경계는 달라도 텍스트 행의 위아래 여백은 균형을 유지한다.
- 숫자·무늬·여백은 같은 카드 컨테이너를 기준으로 함께 축소/확대한다. 고정 px 글자와 줄높이 때문에 작은 공용카드의 아래 테두리에 무늬가 붙지 않게 한다. 개인카드·공용카드·확대/비교 카드에도 동일 기준을 적용한다.
- 검증: 320/390/468/1366px에서 가로 넘침과 글자 잘림 없음, 숫자/무늬 행 사이 겹침 없음, 위아래 여백이 균형을 이루는지 확인한다. 카드12장 착지 위치/크기 검증도 유지한다. 완료→다음 레슨 이동/진도 저장, 재연습, 미구현 다음 레슨, 정적 단계 재생 버튼 숨김, 재생 직후 결과·질문의 다시 보기·취소를 검사한다. 다시 보기 중/후 현재 파트와 질문·진행률·진도 저장 위치가 변하지 않고, 반복해도 칩이 중복되지 않으며, 종료 후 정상적으로 다음/답변할 수 있어야 한다. 새 레슨을 추가할 때 모든 파트를 이 기준으로 검사하고 버튼이 남는 파트와 숨기는 이유를 구현 기록에 남긴다.

## 4. 한 장면의 문법

기본은 상황 제시 → 관찰 또는 직접 선택 → 결과 확인이다. 한 장면에서는 새 개념 하나만 다룬다.

- 제목은 질문 또는 결과 한 문장. 본문은 원칙적으로 1~2문장.
- 테이블에는 지금 설명하는 대상만 강조한다. 틀린 선택 직후 곧바로 정답 위치를 자동 선택하지 않는다.
- 정답이면 결과 장면에 머물고 사용자가 다음을 누른다. 도중에 다음 설명으로 자동으로 넘어가지 않는다.
- 오답이면 상태와 칩을 유지하고 이유 한 문장을 표시한다. 재시도할 수 있고 힌트는 별도 버튼으로 제공한다.
- 선택지가 4개 이상이면 모바일 2열을 기본으로 한다. 카드 고르기는 탭 토글과 ‘선택 완료’를 제공한다. 드래그를 필수로 하지 않는다.
- 단순한 숫자·규칙 퀴즈도 가능하면 테이블의 현재 숫자와 연결한다.
- 별도 상황에 들어가면 설명 패널의 작은 표시에 ‘별도 연습’이라고 쓴다. 돌아갈 때 ‘본판으로 돌아가기’로 구분하고 본판 체크포인트를 정확히 복원한다.
- 학습용으로 상대 카드가 보일 때는 ‘승부 원리 보기’ 등 맥락을 표시한다. 실제 플레이에서도 항상 보인다고 오해하게 하지 않는다.

## 5. 모션 계약

기존 Web Animations API 구현을 유지한다. Motion·GSAP은 필요해진 시점에 시각 함수만 교체할 수 있게 한다. 이번 확장 자체의 선행 조건으로 설치하지 않는다.

1. 카드 이동: `playCardFlight({card, source, target, reducedMotion, signal})`. 첫 카드는 슬롯 0, 두 번째 카드는 슬롯 1의 실제 DOM 위치·크기로 착지한다. 공통 animationTiming.cardFlight(360ms), ease-out을 사용한다.
2. 베팅: `playerAction(player, type, from, to)` → `playPlayerAction(...)`. from/to는 해당 스트리트 누적 베팅액, 이동량은 to−from. 콜·베팅·레이즈 모두 기존 함수 사용. 공통 animationTiming.chipFlight(450ms)를 사용한다.
3. 체크: 칩 0개 이동, 공통 animationTiming.check(760ms)의 두 번 노크를 사용한다. ‘정확히 두 번 두드려야만 체크’라는 규칙으로 가르치지 않는다.
4. 기본 순서: 행동자 강조220ms → 효과 재생 → 상태 한 번 확정 → 결과330ms 관찰. 카드 사이200ms 간격을 사용한다. 시간은 animationTiming에서 가져온다.
5. 신규 효과는 폴드, 공용카드 공개, 팟 정리, 팟 지급, 버튼 이동이 실제 필요한 레슨에서만 추가한다. 모두 Promise와 AbortSignal 계약을 따른다.
6. 애니메이션 함수 안에서 칩·정답·레슨 상태를 수정하지 않는다. 취소 후 완료 콜백이 새 장면을 덮어쓰지 못하게 한다.
7. 이전·레슨 변경·리사이즈·컴포넌트 해제는 재생을 취소한다. 다시 보기 버튼은 재생 중 비활성화한다. 빠르게 두 번 누른 동작으로 이중 지급하지 않는다.
8. 모션 감소 환경에서도 동일한 결과가 된다. 움직임은 생략하거나 짧은 강조로 대체한다.
9. 화면 회전·리사이즈 중 이동은 취소하고 현재 단계의 확정 체크포인트로 복구하여 다시 재생할 수 있게 한다. 잘못된 칸으로 착지한 채 다음 장면으로 넘어가지 않는다.

## 6. 금액·역할·카드 표시 규칙

- ‘팟’은 현재 핸드에 모인 칩 총액이다. 앞에 놓인 베팅 칩도 포함한다. 중앙에 모을 때 같은 칩을 다시 더하지 않는다.
- ‘이번 단계에 낸 칩’과 ‘이번 판 전체에 낸 칩’을 별도 값으로 관리한다.
- 새 스트리트에서는 전자의 값과 맞출 금액을 0으로 만든다. 이미 모인 팟은 유지한다.
- 금액 선택의 ‘총 30으로 레이즈’와 ‘20 추가’를 분명히 구별한다. 같은 버튼에서 어떤 금액인지 숨기지 않는다.
- 폴드 후 낸 칩은 팟에 남고 승부 참가 자격만 사라진다. 올인은 남은 칩 0이지만 승부 참가 자격이 남는다.
- ‘플레이어 2’와 배열 인덱스 2를 혼용하지 않는다. 문서에서는 P0=나, P1=플레이어 2, …, P5=플레이어 6을 사용한다.
- 현재 자리 배치는 P0 아래 → P1 왼쪽 아래 → P2 왼쪽 위 → P3 위 → P4 오른쪽 위 → P5 오른쪽 아래이다. 이것이 시계 방향이다.
- BTN·SB·BB는 좌석 번호에 하드코딩하지 않는다. 역할이 이동해도 카드와 플레이어의 identity는 유지한다.
- 상대 카드의 공개 여부와 실제 카드 데이터는 별도다. 카드 앞면은 하드코딩된 8♠/Q♥를 모든 좌석에 복제하지 않는다.

## 7. 범위 경계

포함: 25개 고정 시나리오, 직접 선택 문제, 복습, 실습에 필요한 규칙 계산, 카드·칩·버튼 연출, 접근성, 모바일 검증.

제외: 자유 포커 엔진, 무작위 상대 AI, 멀티플레이, 서버·회원가입·클라우드 저장, 광고·결제, 실전 전략, 실제 대회 운영 엔진. 미니멈 미달 올인 레이즈의 베팅 재개, 데드 버튼, 오프라인 오선언·미스딜·번카드 처리 등은 새 필수 레슨으로 추가하지 않는다. 구현 데이터가 해당 예외를 실수로 만들어내지 않게 검증한다. 지원하지 않는 예외를 일반 규칙으로 잘못 시뮬레이션하지 않는다.

홀수 칩 분배 문제는 나누어떨어지는 팟으로 구성한다. 나머지 칩이 생기는 임의 예시를 추가하려면 먼저 별도 규칙을 설계해야 한다.

## 8. 기술 방향

기존 `Table`, `LessonPanel`, `ActionEffect`, 애니메이션 어댑터를 재사용한다. 지금의 전역 숫자 stage 0~10을 수백 개 조건문으로 확장하지 않는다. 레슨 ID·단계 ID·시나리오의 초기 상태와 사건 목록으로 분리한다.

스크립트형 교육 시나리오이므로 임의의 모든 게임 분기를 지원하는 엔진은 불필요하다. 그러나 칩 계산·순서·5장 평가·팟 자격은 순수 함수로 계산하고 테스트한다. 화면에 보이는 숫자와 정답을 서로 다른 상수로 두지 않는다.

공통 기반은 기존 3개 체험을 그대로 재현하는 작은 변경부터 검증한다. 각 신규 공통 기능은 처음 사용하는 레슨과 함께 추가한다. 상세 파일 경로·인터페이스·회귀 검사는 연결된 구현계획을 따른다.

## 9. 완료 기준

- 25개 레슨 각각에 목적, 구체적 테이블 상태, 학습자 입력, 정답/오답 피드백, 다음 단계 조건이 존재한다.
- 숫자·카드·순서가 일관되고 각 핸드의 카드 중복과 칩 생성·소멸이 없다.
- 320/390/474px 모바일과 1366px 데스크톱에서 실행된다. 가로 넘침 없음. 474×884 기본 장면은 현재처럼 주요 행동까지 한 화면에 들어오도록 한다.
- 데스크톱에서 짧은 설명→금액 질문→오답 힌트로 이동해도 테이블 패널 높이와 카드·좌석 위치가 같아야 한다. 설명 패널만 내용에 따라 높이가 달라진다.
- 짧은 높이·글자 확대에서는 필요한 세로 스크롤을 허용한다. 스크롤 제거를 위해 설명을 잘라내거나 글자를 지나치게 줄이지 않는다.
- 검증 전에 완료라고 보고하지 않는다. 레슨마다 테스트·빌드·일반 모션 브라우저 확인 결과를 남긴다.
