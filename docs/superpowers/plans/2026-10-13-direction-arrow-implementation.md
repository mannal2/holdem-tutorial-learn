# 공통 화살표 구현 기록 — 2026-10-13

사용자 승인: 화면 크기에 따라 화살표 끝이 플레이어 설명에 가려지는 문제를 공통 컴포넌트에서 해결하고 앞으로 같은 기준을 사용한다.

- 고정0~100 좌표와 모바일/데스크톱별 경로 문자열을 제거했다. 레슨 데이터에는 from/to 플레이어ID와 힌트 조건만 남겼다. 기존 체험 BTN→SB/BB→첫 행동자와03 BTN→SB/SB→BB가 같은 컴포넌트를 사용한다.
- DirectionArrow는 실제 설명 버튼의 getBoundingClientRect를 기준으로 시작/끝을 박스에서12px 밖에 배치한다. 머리는10×10px, 선2px, 점선5/4px를 유지한다. 카드·배지·라벨 위로 z-index를 올려 덮지 않는다.
- 경로는 이웃한 자리의 가장자리를 따라 굽어진다. 작은 화면의 세로 연결은 중앙 보드 옆 빈 공간을 따라가며, 도착점은 설명 박스 가장자리 안쪽을 향한다. 실제 경계로 계산하므로 화면별좌표를 추가하지 않는다.
- ResizeObserver로 테이블·두 설명 버튼·두 좌석 크기를 관찰한다. 레슨 파트와 출발/도착이 바뀌면 다시 측정한다. 컴포넌트 해제/대상 변경에서는 observer를 정리한다. 힌트 후 표시 조건과 화살표 없는 파트의 숨김은 유지한다.
- 예전 Table의 모바일 판별 hook은 화살표 계산에만 필요했으므로 제거했다. 테이블 반응형 CSS와 카드/칩 애니메이션은 변경하지 않았다.
- 구현계획과 디자인 명세에 공통 컴포넌트 사용과 from/to 데이터 계약, 간격·머리 크기·겹침/잘림 검증 기준을 추가했다.

## 검증

- 변경 전 공통 화살표 머리 계약 검사 실패 확인. 초기 경로 계산 중 실제 좁은 화면의 보드 겹침을 픽셀 검사로 발견해 공통 경로를 보완했다.
- 세 경로를1366/1100/902/801/800/475/390/320px에서 실제 창 크기를 연속 변경하며 검사했다. 선101지점과 머리3꼭짓점이 플레이어 설명·카드·배지·라벨·팟·보드·덱 영역에 겹치지 않음, 테이블 밖으로 잘리지 않음, 시작/끝12px 간격과10px 머리 크기를 확인했다.
- 창 크기 변경 없이 설명 박스 높이를 바꿔도 자동으로 다시 계산하고12px 도착 간격을 유지하는 검사 통과.
- 902px03 화면과320px기존 체험 캡처를 직접 확인했다. 화살표가 설명 아래 숨지 않고 충분한 길이로 보인다.
