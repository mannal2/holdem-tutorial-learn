# 한 판씩 — 25개 레슨 상세 구현계획

> **For agentic workers:** `superpowers:executing-plans`를 사용하여 사용자가 지정한 작업을 하나씩 구현한다. 실행 담당은 사용자가 선택한 Sol이다. 전체 25개를 한 번에 구현하거나 작업 모델을 임의로 변경하지 않는다. 체크박스는 실제 검증 후에만 완료로 표시한다.

**Goal:** 현재의 테이블 중심 디자인과 애니메이션을 유지하면서, 사용자가 규칙을 직접 판단하는 25개 레슨을 구현한다.

**Architecture:** React 화면과 시각 효과를 보존하고 레슨 정의·고정 시나리오·순수 규칙 계산을 분리한다. 시나리오 사건의 확정 상태를 재구성해 이전/재생/진도 복원에서도 칩이나 카드가 중복되지 않게 한다. 자유 포커 엔진은 만들지 않는다.

**Tech Stack:** 기존 React 19.2.8, Vite 8.3.0, JavaScript/JSX, CSS, Web Animations API, node:test, Playwright. 새 애니메이션 라이브러리 설치는 필요 없다.

**Spec:** [학습·디자인 명세](../specs/2026-10-12-holdem-learning-design.md). 구현 전 이 명세와 해당 레슨 절을 모두 읽는다.

**상태:** 2026-10-12 작성한 사용자 검토용 계획. 아래 기능들은 현재 구현되어 있다는 뜻이 아니다. 기존 구현은 카드 배분·첫 행동자·콜/체크를 체험하는 3개 장면이다.

## Global Constraints — 반드시 지킬 것

- 현재의 따뜻한 차콜 배경·녹색 펠트·크림 설명 패널과 기존 카드·좌석 디자인을 유지한다. 정확한 색과 화면은 명세 3절 참조.
- 기존 상단 헤더·상시 목차·하단 홍보 문구·중복 테이블 캡션을 복원하지 않는다.
- 800px 이하 테이블 위/설명 아래, 초과 테이블 왼쪽/설명 오른쪽을 유지한다.
- 데스크톱에서는 왼쪽 테이블 높이를 같은 화면 크기에서 고정하고, 오른쪽 설명 패널만 내용에 따라 늘린다. 윗선만 맞추며 아랫선은 달라도 된다. 상세 기준은 명세 3.1절을 따른다.
- 일반 데스크톱에서는 한 화면 학습을 기본으로 하며 긴 설명은 단계로 나눈다. 모바일은 필요한 페이지 세로 스크롤을 허용한다. 작은 창 높이·글자 확대는 데스크톱에서도 페이지 스크롤을 허용한다.
- 기본 6인, SB 5 / BB 10, 앤티·레이크 없음. P0=나, P1~P5=플레이어 2~6.
- 사용자 확정: 3~17은 한 판 중심 + 필요한 부분만 별도 연습.
- 사용자 확정: 25는 준비된 상황을 직접 푸는 평가. 자유 선택에 반응하는 상대 AI는 제외.
- 사용자 확정: 레슨 자유 선택 + 해당 브라우저에 진도 저장. 별도 회원가입은 없다.
- 패널 상단의 레슨 표시는 현재 lessonId의 등록 정보에서 가져온다. 정식 레슨은 해당 번호(LESSON 01 등), 번호 없는 첫걸음 체험은 이름으로 표시한다. 내부 단계·구간 번호로 레슨 번호를 만들지 않는다.
- 최신 커리큘럼의 18·19 족보 레슨을 포함한다. 예전 대화의 ‘족보는 별도’보다 이번 목록을 우선한다.
- 실제 앱 코드 변경은 다음 구현 단계에서 한다. 이 문서를 읽었다는 이유만으로 전체 구현을 시작하지 않는다.


### 애니메이션 학습 속도 — 사용자 확정(2026-10-13)

- 모든 레슨은 src/animation.mjs의 animationTiming과 공통 재생 함수를 사용한다. 레슨 데이터나 개별 컴포넌트에 별도 속도를 하드코딩하지 않는다. 새로운 효과가 필요한 경우에도 공통 기준에 맞춰 정의하고 기존 효과의 속도를 우회하지 않는다.
- 일반 모션 기준: 카드 배분·공용카드 비행360ms, 공용카드 앞면 전환200ms, 칩 이동450ms, 폴드520ms, 체크 두 번 노크760ms. 베팅·콜·레이즈·칩 반환·팟 지급은 같은450ms 칩 이동을 사용한다.
- 실제 행동 없는 순서 미리보기는 자리 강조220ms → 관찰 유지450ms → 결과 멈춤330ms로 약1초씩 진행한다. 카드·칩을 움직이지 않고 베팅/체크 또는 행동 순서 소비로 기록하지 않는다.
- 행동 전 플레이어 강조220ms, 행동 후 결과 멈춤330ms, 카드 한 장 배분 후 멈춤200ms를 사용한다. 누구의 행동인지와 도착 결과를 읽을 시간을 확보하며 모든 효과에 동일한 배율을 적용하지 않는다.
- 폴드 카드는 아래로 내려가며 사라진 뒤 원래 카드 모습으로 돌아오거나 깜빡이지 않는다. 사라진 최종 프레임을 폴드 상태가 화면에 반영될 때까지 유지하고 효과를 정리한다. 폴드 후 빈 카드 슬롯의 테두리, 어두워진 좌석과 폴드 표시는 유지한다. 재생 취소 시 유지된 효과도 정리한다.
- 체크 파문은220ms로 재생하고, 노크 전체 시간의28%와66% 지점에 시작해 손의 두 접촉과 동기화한다. 체크를 늦춰도 두 번 노크 리듬과 칩 이동 없음은 유지한다.
- 모션 감소 설정에서는 시각 이동을 생략하고 각 공통 대기는60ms로 유지한다. 일반 모션을 늦췄다는 이유로 모션 감소 대기도 늘리지 않는다.
- 속도와 규칙 상태를 분리한다. 칩/카드 상태는 이동 완료 후에만 확정하며, 취소/반복 재생에서도 중복 지급이나 늦은 상태 변경이 없어야 한다.
- 신규 레슨 검증에서 공통 속도 사용, 체크 접촉/파문 동기화, 이동 완료 전 상태 유지, 취소와 모션 감소 동작을 확인한다. 순차 배분/행동의 테스트 대기는 실제 재생 완료를 기다리며, 이전 속도의 고정 시간에 의존하지 않는다.

### 공통 순서 화살표 — 사용자 확정(2026-10-13)

세로 바깥 경로 후속 변경 검증:55개 단위검사·빌드·전체 브라우저 회귀 검사 통과. 레슨05 포함8개폭에서 겹침/잘림/12px 끝점 간격/10px 화살촉을 검사하고902/320px 화면을 직접 확인했다. 좁은 화면의 바깥 여백 확보를 위해 좌석을 최소 보정하며,320px 덱을 위로 옮겨 개인카드 간격을 유지한다.

- 모든 레슨의 순서 안내는 DirectionArrow 공통 컴포넌트를 사용한다. 데이터에는 direction:{from:플레이어ID,to:플레이어ID,onHint?:true}만 지정하며 모바일/데스크톱별 SVG 좌표나 경로 문자열을 하드코딩하지 않는다.
- 실제 렌더링된 출발/도착 플레이어 설명 박스의 경계와 테이블 크기를 측정해 경로를 계산한다. 출발점·화살표 끝은 설명 박스에서12px 떨어뜨리고, 머리는 길이/너비10px, 선은2px로 유지한다. 박스 위에 화살표를 겹쳐 올려 가독성 문제를 해결하지 않는다.
- 경로는 이웃한 자리 사이의 테이블 가장자리를 따르며 중앙 팟·보드를 가리지 않는다. 세로로 이어진 좌석은 왼쪽/오른쪽 바깥으로 볼록한 곡선을 사용한다. 곡선 폭은 실제 바깥 여백에 맞춰 줄이고, 좌우 좌석 바깥에 최소22px 공간을 확보한다.320px에서는 덱 위치도 카드와 겹치지 않도록 조정한다. 대각선 경로는 기존 계산을 유지한다. 카드·역할 배지·라벨과도 겹치지 않도록 현재 레슨 경로를 검증한다. 레슨05의첫행동자/정답/뒤쪽순서화면도8개폭(320/390/475/800/801/902/1100/1366)에서 실제 경로를 검사한다.
- ResizeObserver로 테이블·설명 박스·좌석 영역 크기를 관찰하고, 파트가 바뀔 때도 위치를 다시 측정한다.800px 경계에서 레이아웃이 바뀌거나 설명 박스 크기가 달라져도 같은 간격과 머리 크기를 유지한다. 숨김/힌트 조건은 기존 레슨 데이터대로 유지한다.
- 새 순서 경로를 추가하면320/390/475/800/801/902/1100/1366px에서 실제 창 크기를 변경하며 머리/선의 겹침·잘림 없음,12px 간격과10px 머리 크기를 확인한다. 기존 칩/카드 이동과 레슨 진행을 변경하지 않는다.

### 공통 테이블의 문구와 카드 위 라벨 — 사용자 확정(2026-10-13)

- 공통 Table에서 펠트의 ‘한 판씩’ 워터마크와 보드 아래 상시 안내를 제거한다. ‘공용카드 N장’, ‘공용카드는 아직 없어요’, ‘모두 함께 쓰는 공용카드’ 등의 상시 시각 문구를 신규 레슨에서 복원하지 않는다. 모든 테이블 모드에 적용한다.
- 공용카드를 처음 배우는 레슨에서는 해당 파트의 설명창으로 개념을 안내한다. 화면 읽기 도구용 보드 설명(aria-label)은 유지한다.
- 행동·결과 라벨은 좌석의 고정 top 좌표 대신 해당 개인카드 영역 위에 배치한다. 카드 영역은 카드의 실제 높이에 맞게 늘어나고, 라벨 아래와 카드 위 사이에6px 간격을 확보한다. 강조 테두리까지 고려해 시각적 겹침이 없어야 한다. 카드 강조 크기는 유지하며 가독성 문제를 해결하려고 라벨 글자를 더 작게 줄이지 않는다.
- 모바일에서 위 라벨과 중앙 보드도 겹치지 않아야 한다. 새 카드 크기·강조 효과를 도입할 때 카드/라벨/보드 간격을 함께 확인한다. 테이블 높이를 설명 길이에 따라 늘리는 방식으로 해결하지 않는다.
- 새 레슨 구현 시 공통 컴포넌트를 재사용하고320/390/475/1366px에서 상시 문구 없음, 라벨과 카드·보드의 겹침 없음, 카드 배분 슬롯 착지·테이블 높이 유지 여부를 검증한다.

### 완료 버튼·애니메이션 재생·카드 여백 — 사용자 확정(2026-10-13)

- 레슨 완료 화면의 큰 주 버튼은 바로 다음 번호의 정식 레슨이 구현된 경우 ‘다음 레슨: 제목 →’으로 표시한다. 클릭하면 그 레슨의 첫 단계로 이동하고 완료 기록은 유지한다. 미구현 수업을 건너뛰거나 첫걸음 체험을 정식 순서에 끼우지 않는다.
- 다음 레슨이 있으면 ‘이 레슨 다시 연습 ↻’은 주 버튼 아래 보조 버튼으로 배치하고 터치 높이는 최소44px를 유지한다. 다음 레슨이 미구현이거나 마지막 수업이면 재연습을 큰 주 버튼으로 유지한다. 완료 화면에는 애니메이션 다시 보기 버튼을 표시하지 않는다.
- 새 정식 레슨을 구현·등록할 때마다, 사용자의 별도 요청 없이 바로 이전 정식 레슨의 완료 화면도 검증한다. 큰 주 버튼이 새 레슨의 정확한 번호·제목으로 연결되고 재연습 버튼이 아래 보조 위치로 전환되는지, 클릭하면 새 레슨의 첫 단계로 이동하는지, 이전 레슨 완료 기록과 새 레슨 진도가 유지·저장되는지 확인한다. 이전 레슨을 이미 완료한 상태에서 새로고침해도 버튼 전환이 적용되어야 한다. 모바일과 데스크톱에서 재연습 동작·배치까지 검사하고 해당 레슨 구현 기록에 결과를 남긴다. 이전 레슨이 아직 미구현이면 이 연결 검증은 적용 대상 없음으로 기록한다.
- 애니메이션 다시 보기는 이미 본 애니메이션을 반복한 뒤에도 현재 결과·질문 파트에 그대로 머무르는 경우에만 표시한다. 처음 재생하고 다음 파트로 진행하는 화면, 재생 경로가 없는 정적 설명·질문, 레슨 완료 화면에서는 숨긴다. 현재 파트의 replayFrom이 같은 시나리오의 재생 구간을 가리키고, 그 구간의 끝(playTo)이 현재 checkpoint와 일치할 때만 허용한다. 현재 파트 자체에 처음 진행할 playTo가 있으면 다시 보기 버튼을 표시하지 않는다.
- 버튼은 ‘↻ 애니메이션 다시 보기’로 표시한다. 재생 중에는 ‘↻ 다시 보는 중…’으로 표시하고 비활성화하여 중복 재생을 막는다. 일반 진행은 주 버튼이 담당한다. 다시 보기에서는 stepId·제목·질문·진행률·오답/힌트·선택 상태를 유지하고, 재생 완료 시 현재 파트의 원래 확정 테이블 상태를 복구한다. 자동으로 다음 파트로 이동하거나 진도/완료 조건을 추가하지 않는다. 질문 답변과 주 버튼도 재생 중에는 비활성화한다. 이전·레슨 변경·리사이즈·새로고침에 의한 취소 시 늦은 카드/칩 변경이 없어야 한다.
- 카드 바깥 크기·착지 슬롯·뒷면 패턴은 보존한다. 숫자/무늬를 내부의 위/아래 두 행에 배치하고, 내용 영역의 상하 여백은 카드 내부 높이의8%, 좌우는 내부 너비의12%로 유지한다. 숫자는 내부 높이의40%, 무늬는34% 크기와 line-height:1을 사용한다. 무늬에 따라 실제 잉크 경계는 달라도 텍스트 행의 위아래 여백은 균형을 유지한다.
- 숫자·무늬·여백은 같은 카드 컨테이너를 기준으로 함께 축소/확대한다. 고정 px 글자와 줄높이 때문에 작은 공용카드의 아래 테두리에 무늬가 붙지 않게 한다. 개인카드·공용카드·확대/비교 카드에도 동일 기준을 적용한다.
- 검증: 320/390/468/1366px에서 가로 넘침과 글자 잘림 없음, 숫자/무늬 행 사이 겹침 없음, 위아래 여백이 균형을 이루는지 확인한다. 카드12장 착지 위치/크기 검증도 유지한다. 완료→다음 레슨 이동/진도 저장, 재연습, 미구현 다음 레슨, 정적 단계 재생 버튼 숨김, 재생 직후 결과·질문의 다시 보기·취소를 검사한다. 다시 보기 중/후 현재 파트와 질문·진행률·진도 저장 위치가 변하지 않고, 반복해도 칩이 중복되지 않으며, 종료 후 정상적으로 다음/답변할 수 있어야 한다. 새 레슨을 추가할 때 모든 파트를 이 기준으로 검사하고 버튼이 남는 파트와 숨기는 이유를 구현 기록에 남긴다.

1. 재생 중 이전·레슨 변경·새로고침: 이전 애니메이션이 새 상태에 칩을 더하지 않아야 한다. 공통 기반 F0/F1, 레슨 8·20에서 검사.

### B2. 데이터와 함수 계약

아래 이름은 권장 구현 계약이다. 변경이 필요하면 먼저 해당 문서의 모든 사용처와 테스트 계약을 함께 수정한다. TypeScript 도입 없이 JSDoc으로 설명하면 충분하다.

**카드:** `Card = { id: 'Qs', rank: 12, suit: 's' }`. suit는 s/h/d/c. A=14. 한 핸드의 개인카드·보드에 같은 id가 두 번 존재하지 않는다.

**TableState:**

- `street`: preflop/flop/turn/river/showdown/complete.
- `buttonId`, `smallBlindId`, `bigBlindId`, `smallBlind:5`, `bigBlind:10`.
- `seats`: 시계 방향 고정 순서. 각 요소 `{id, name, stack, streetCommitted, handCommitted, status, hole, dealtCount, revealed}`. status는 active/folded/allIn/out.
- `board`: 실제 카드 배열, `boardCount`: 현재 공개한 0/3/4/5장.
- `currentBet`, `lastFullRaise`: 현재 맞출 총액/직전 정상 증가분.
- `pendingActorIds`: 아직 행동할 사람들의 순서. BB의 최초 옵션도 포함.
- `potTotal`: 별도 누적 저장하지 않고 현재 handCommitted의 합에서 파생한다. 지급 사건은 handCommitted를 정리하고 stack에 배분한다.
- 중앙 정리 연출을 위해 `collectedCommitted`를 별도로 둘 수 있다. 이 값은 칩 위치 표현에만 쓰고 돈을 다시 더하지 않는다.

**시나리오:** `{id, initialState, events, checkpoints}`. events는 순서가 확정된 사건, checkpoints는 이름 → 사건 완료 개수. 임의 베팅을 받아 대응하는 게임 엔진이 아니다.

**사건:** 처음 필요한 것부터 추가한다: `postBlind`, `deal`, `act`, `collect`, `revealBoard`, `revealHole`, `award`, `moveButton`, `startHand`. `act`는 check/fold/call/bet/raise와 이번 스트리트 총액 `to`를 사용한다. 올인은 별도의 베팅 종류로 전부 치환하지 말고 합법 action 후 stack=0인 상태로 표시한다.

**순수 함수:**

- `applyEvent(state, event) -> nextState`: 기존 객체를 수정하지 않는다. 음수 칩, 초과 인출, 중복 지급 금지.
- `stateAt(scenario, eventCount) -> TableState`: initialState부터 완료된 사건만 적용. 이전·재시작은 여기서 재구성한다.
- `nextSeat(seats, fromId, eligibleIds) -> id|null`: 시계 방향으로 다음 대상 찾기. 게임에서 빠진 자리 처리.
- `callAmount(state, playerId) -> number`: `min(stack, max(0,currentBet-streetCommitted))`.
- `minimumRaiseTo(state) -> number`: 정상 베팅이 있는 기본 상황은 currentBet+lastFullRaise. 미니멈 미달 올인 레이즈는 고정 예시에서 생성하지 않는다.
- `isRoundComplete(state) -> boolean`: pending이 없고, 올인이 아닌 생존자의 금액이 맞았거나 생존자가 한 명만 남은 상태. 구현 단계 9까지는 올인 없는 예시로 검증한다.
- `evaluateSeven(cards) -> {category, tiebreak, bestFive}`와 `compareHands(a,b) -> -1|0|1`: 레슨 17에서 추가.
- `buildPots(seats) -> {pots:[{amount,eligibleIds}],returns:[{playerId,amount}]}`: 레슨 23에서 추가. 낸 칩은 폴드한 사람도 포함하고 자격에서는 제외한다.

**레슨:** `{id:'01', title, steps:[...]}`. `Step`은 `{id, scenarioId, checkpoint, title, body, focus, question?, playTo?, nextLabel, reviewLessonId?}`.

- `focus`는 강조 seatIds/cardIds/role 등 시각 정보이다. 정답 처리나 칩 계산을 포함하지 않는다.
- `question.kind`는 choice/seat/cards. `{prompt, options?, acceptedAnswers, feedbackByAnswer, hint}`. 복수 정답 여부를 명시한다.
- ‘정확히 5장’ 문제는 카드 id의 순서를 무시한다. 같은 가치의 최선 조합이 여러 개면 모두 인정한다.
- `playTo`는 현재 checkpoint 이후 어디까지 재생할지 가리킨다. 재생 도중 React state는 화면용 중간 결과일 뿐, 저장은 확정 단계만 한다.
- 결과 확인 단계도 별도 stepId를 갖는다. 성공과 동시에 다음 레슨으로 자동 이동하지 않는다.

**런타임:** `getStep(lessonId,stepId)`, `answer(value)`, `next()`, `previous()`, `replay()`, `goToLesson(id)`를 UI에 제공한다. 관찰 문제는 지정 재생 완료, 질문 문제는 정답 확인, 완료 장면은 다음 버튼으로 전진한다.

**뒤로/재생 규칙:** 이전은 이전 설명 단계의 기준 상태로 간다. 다시 보기는 현재 결과·질문 파트의 화면과 진도를 유지한 채 지정된 이전 재생 구간만 실행하고, 종료 후 현재 파트의 확정 상태를 복구한다. 재생 중에는 다시 보기 버튼이 비활성화되며 다음 파트로 자동 이동하지 않는다. 레슨 경계를 넘어 뒤로 가면 직전 레슨 마지막 단계로 간다. 1번 첫 단계에서는 이전 비활성. 별도 연습 후에는 지정된 본판 checkpoint로 돌아온다.

### B3. 정답과 게임의 합법성 구분

예: “지금 가능한 행동을 모두 고르세요”는 폴드/콜/레이즈를 모두 인정해야 한다. “금액을 맞추는 행동을 골라보세요”는 콜이 학습 답이다. 폴드를 골랐을 때 “폴드도 가능하지만, 이번에는 금액을 맞추는 행동을 찾아보세요”라고 쓴다. 불가능한 체크에는 “아직 맞춰야 할 10칩이 남아 있어요”라고 쓴다.

자유 베팅 슬라이더를 먼저 만들지 않는다. 지정된 총액 선택지 또는 금액 버튼을 사용한다. 이 선택 덕분에 완전한 포커 엔진 없이도 정확한 학습을 제공할 수 있다.

## G. 전체 검증 계획

### G1. 순수 데이터·규칙 검사

- 모든 fixture의 카드 id 중복 검사. 동시에 같은 핸드에 쓰이지 않는 독립 예시는 각각 따로 검사. 별도 예시는 체크포인트에서 시작할 수 있으나, 역할·칩 기여에 모순이 생기지 않도록 참가/비참가 자리와 그 체크포인트까지의 필요한 준비 사건을 fixture에 명시한다.
- 각 사건 후 `sum(stack)+sum(handCommitted)=scenario.initialTotal`. 반환·지급 뒤에도 성립. 초기총액600/650/510/200/100을 fixture별 명시.
- 현재스트리트기여 ≤ 핸드기여, stack≥0. 보드0/3/4/5, 개인카드0~2.
- 모든 레슨 stepId 유일, 참조 scenario/checkpoint/다음레슨/복습레슨 존재.
- 정답 경로로 레슨 끝까지 도달, 모든 질문에 유효한 acceptedAnswers 존재. 안내 단계는 정답 문제로 오인하지 않음.
- 본판 체크포인트 표와 assessment 표의 숫자를 각각 단정(assert). 테스트에서 화면 숫자를 읽어 그대로 정답으로 삼지 않음.
- 최소 레이즈·라운드 종료·카드 평가·팟 자격은 해당 레슨의 표본과 경계 사례를 검사.

### G2. 브라우저 검사

- 명세 3.1절의 데스크톱 높이 고정 규칙은 레슨01 구현에서 공통 CSS에 반영했다. 이후 신규 레슨에서도 같은 높이와 카드 위치가 유지되는지 회귀 검사한다.
- 데스크톱(1366×900 및 넓은 화면)에서 같은 viewport를 유지한 채 짧은 안내, 콜 금액 질문, 오답 힌트로 이동하여 table-panel/table-stage의 높이와 카드·좌석 위치가 변하지 않는지 검사한다. 설명 패널만 길어져야 한다.
- 데스크톱 두 패널의 윗선이 같고 아랫선이 달라도 정상이다. 일반 분량의 본문과 핵심 조작은 화면 안에 표시하고, 설명 패널 내부 스크롤을 기본으로 만들지 않는다.

- 1366×900, 474×884, 390×844, 320×740. 기본 단순장면에서 가로스크롤0, 버튼/카드 겹침0. 작은 높이에서 세로스크롤은 허용.
- 474×884 대표 장면의 테이블+설명+핵심버튼이 한 화면에 들어오도록 확인. 긴 족보 설명은 작은 글씨 대신 단계 분리.
- 기본 타겟은 버튼44px 이상. 카드 선택은 작은 테이블 카드 대신 확대패널로 제공하며 인접한 카드 오탭을 줄인다.
- 키보드만으로 자리/선택/레슨목록 조작. 질문 피드백 aria-live, 선택 카드 aria-pressed, 카드의 숫자·무늬 접근성 이름.
- 숫자변화만 보지 말고 실제일반모션을 검사: 개별카드착지, 칩출발/도착, 체크2회, 폴드회수, 보드공개, 팟지급.
- 모든 신규 애니메이션에 최소1개 취소검사: 재생중이전/레슨이동/리사이즈 중 하나. 다시 보기 버튼은 재생 중 비활성화하므로 취소 수단으로 사용하지 않는다. 공통런타임에서 전체 취소행동을 검사.
- 모션감소에서도 완전히 같은 확정 상태. 브라우저pageerror0.
- 200% 글자확대에서 내용 유실/필수버튼 가림 없음. 한 화면에 전부 보이게 하는 조건보다 접근성 우선.

### G3. 실행 명령과 완료 증거

기존 명령을 유지한다.

```text
npm run check
npm run test:e2e
```

서버 `http://127.0.0.1:5188/`를 실행한 상태에서 브라우저 검사한다. 현재 `npm test`의 파일 glob을 수정할 경우 기존9개 테스트와 새 하위폴더 테스트가 모두 실행되는지 출력으로 확인한다. 새 E2E 실행기는 구현된 레슨만 대상으로 하고 준비 중인 레슨을 통과한 것처럼 집계하지 않는다.

각 레슨 완료 보고에는 (1) 구현된 장면, (2) 추가/재사용한 효과, (3) 테스트 결과, (4) 모바일 화면 캡처 경로, (5) 남은 제한을 짧게 적는다. CSS만 바뀐 경우에도 해당 화면을 실제로 확인한다.

## H. 의도적으로 넣지 않는 기능과 이유

- 자유 플레이/상대 AI: 사용자가 고정 문제 풀이를 선택했다. 규칙 학습보다 게임 엔진 구현량이 커진다.
- Motion·GSAP 강제 도입: 현재 효과를 유지할 수 있다. 추후 시각 어댑터 내부 교체로 도입 가능.
- 항상 보이는25개목차: 모바일 학습 공간을 차지한다. 작은 버튼으로 목록을 연다.
- 텍스트로 된 긴 규칙표: 원래 문제인 ‘실제 상황에서 기억나지 않음’을 해결하기 어렵다. 한 개념씩 동작·선택에 연결한다.
- 무작위 카드: 아직 잘못된 족보 예시/불가능한 학습 경로의 위험이 크다. 고정 fixture를 추가하는 방식으로 문제를 확장한다.
- 미학습 드문 예외 강제출제: 미니멈 미달 올인 레이즈의 재개, 데드버튼, 오선언/번카드 등은 요청된25개 안에서 필수로 확장하지 않는다. 구현이 해당 예외를 요구하면 무시하지 말고 별도 설계 논의로 표시한다.
