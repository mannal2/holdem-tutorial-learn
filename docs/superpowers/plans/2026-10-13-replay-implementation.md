# 애니메이션 다시 보기 수정 기록 — 2026-10-13

## 원인과 변경 기준

다시 보기가 일반 진행과 같은 play 경로에서 go(nextId)를 호출해 다음 파트로 이동했다. 별도 재생 시에는 현재 화면을 유지하고 사건 구간만 실행한 뒤 원래 checkpoint 상태를 복구한다. 첫 재생은 주 버튼으로 진행한다.

구현계획과 디자인 명세의 이전 ‘재생 전에도 표시 / 재생 중 처음부터 다시 보기’ 규칙을 교체했다. 이제 이미 본 애니메이션을 재생한 뒤 같은 결과·질문에 머무르는 파트에만 버튼을 표시한다. 재생 중 다시 보기와 답변은 비활성화한다.

## 구현과 검증

- canReplay는 결과/질문의 replayFrom 재생 구간이 같은 시나리오이고 playTo가 현재 checkpoint와 일치할 때만 참이다. 완료·첫 재생·정적 파트에서는 거짓이다.
- play(replayStep)는 화면의 stepId를 바꾸지 않는다. 재생 종료 시 go를 호출하지 않고 재생 cursor만 해제한다. visit·오답/힌트·진행률을 유지하여 질문 컴포넌트도 다시 생성하지 않는다. 재생은 완료 조건을 추가하지 않는다.
- 재생 중 중복 호출/답변을 차단한다. 이전·레슨 변경·리사이즈·새로고침 취소에서는 원래 checkpoint로 돌아가며 늦은 이벤트를 무시한다.
- 공통 런타임을 사용하는 첫걸음 체험도 같은 규칙을 적용한다. 일반 카드 배분/콜/체크 진행은 유지한다. 기존 회귀 검사의 재생 진입은 결과·질문으로 조정하고 칩 중복 검증은 유지했다.
- RED: 시작 전 노출, 질문의 stepId 변경, visit/피드백 초기화를 새 테스트에서 재현했다. GREEN: 현재 파트 유지·반복 재생·중복 호출·답변 차단·취소 테스트 통과.
- 단위검사40개 및 빌드 통과.1366/468px 브라우저에서 01·02 전체15파트의 버튼 표시를 확인했다. 세 재생 파트의 제목·질문·진행 위치·오답·칩 보존, 새로고침 복원, 재생 후 답변 진행을 확인했다. 일반 모션 리사이즈 취소도 원래 질문과 팟80으로 복구된다.
