# 레슨 01 구현 기록

대상: 25개 레슨 구현계획의 01. 홀덤의 승부 원리. 다른 정식 레슨은 구현하지 않는다.

## 범위와 판단

- 5개 학습 장면(a~e)을 구현하고 카드 선택 결과·승자 결과·완료 확인을 별도 단계로 두어 총8개의 step을 만들었다. 맞힌 뒤 결과를 보고 직접 다음으로 이동한다.
- Ruling: 계획의 ‘다음 레슨’은 아직02가 준비되지 않았으므로 완료 화면에서 같은 레슨 다시 연습을 제공한다. 다음 수업은 목록에서 준비되면 선택한다. 비용: 02 구현 시 완료 화면 연결을 추가한다.
- 첫걸음 체험은 04/05/08이 대체하기 전까지 유지한다. 이번에는01만 선택 가능 상태로 추가했다.
- 사용자 확정 공통 규칙에 따라 데스크톱 테이블 높이 고정을 이번 레슨 작업에 포함했다. 모바일은 기존300px 테이블과 자연스러운 페이지 스크롤을 유지한다.
- Ruling: 첫 레슨은 승부를 미리 보는 장면이므로 아직 배우지 않은 블라인드·스택·베팅·팟·덱 표시를 감추고 개인2/공용5만 강조한다. 실제 상태의 칩600/팟180은 유지한다. 비용: 금액 관련 개념은 이후 레슨에서 표시한다.
- Git 저장소가 없는 현재 승인 폴더에서 작업한다. 커밋·worktree 작업은 없다.

## 구현 계약

- `src/lessons/01-victory.js`: a내2+공용5, b두쌍안내, c네장을고정하고다섯째선택, d투페어/원페어비교, e정확히5장판정, 확인/완료.
- `src/scenarios/main-hand.mjs`: 본판 showdown의 독립 미리보기. 실제 개인카드/보드, 기여액[50,10,50,10,10,50]와 stacks[50,90,50,90,90,50]. 카드 identity는 기존 prototype과 공유하되 stateAt에서 깊은복사한다. 향후 체험 제거 전에 본판 공통 데이터 참조도 함께 이동한다.
- `src/HandFocus.jsx`: 개인2/공용5 출처가 분리된 확대카드, 선택표시, 완성5장 비교.
- `src/Question.jsx`: 카드 탭토글과 선택완료 form, 자리/일반선택 문제. 카드 후보는 자신의 개인카드와 공용카드뿐이다.
- runtime: 카드 집합을 순서 무관하게 판정하며 중복을 거절한다. 필수 안내 단계를 완료조건에 포함하고 visit값으로 다시보기시 선택UI를 초기화한다.
- 카드 평가 엔진은 아직 만들지 않았다. 이 레슨의 안내된 Q/8투페어 예시와 정답을 사용한다. 전체5장 평가/동률 계산은 계획17/19 단계에서 구현한다.
- `Table`의 hand-preview 모드는 미학습 금액/역할을 감추고 비교하는 두 자리와 실제 보드를 강조한다. 일반 체험 모드는 유지한다.
- `styles.css`: 데스크톱 grid 윗선 정렬, table-stage490px(넓은화면550px)/flex성장해제. 설명패널만 내용에 따라 증가. 카드 확대·선택·비교 스타일은 기존 크림·금색·녹색을 유지한다.
- 테스트 명령은 tests/lessons 하위단위검사를 포함하고01브라우저검사를 전체E2E에 연결했다.
